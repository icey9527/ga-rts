# ADR-0012 借鉴 Project Sylpheed 的引擎框架（而不是移植它的战斗模型）

- 状态：已采纳
- 日期：S1 前
- 决策者：用户 + DeepSeek
- 侦察：GLM-5.3-Flash (scout)

## 背景

用户提供了 F:/sqrttt —— Project Sylpheed（仙女计划）的反汇编分析文档，356 个文件 / 9.5 MB，
形态是 IDA Pro 9.1 Hex-Rays 伪 C + 人工分析 md。原 Lua 2D 项目开发时曾以此作参考。

## 关键前提（必须先说清）

**Project Sylpheed 不是 3D RTS，是太空狗斗模拟游戏（Space Combat Sim）**。
玩家驾驶单一机体作战，没有多单位框选指挥、没有编队指令、没有寻路。

因此它的三个东西要分开看：

| 层面 | 能否照搬 |
| --- | --- |
| 引擎框架（调度 / 碰撞 / 消息 / 生命周期） | ✅ 高度可搬，且比我们原 Lua 版更严格 |
| 战斗模型（单机体狗斗 FSM / 炮塔火控 / 锁定） | ⚠️ 部分可搬（炮塔、弹道、前置量），机体狗斗不适用 |
| 玩法形态（单机狗斗） | ❌ 我们的目标是多单位指挥 RTT，与原 Lua 版一致 |

同时：文档里**没有「2D 平面模式 + 3D 空间」的双模式**。
Sylpheed 只有「3D 主场景 + 2D HUD」这一常规结构。
双模式来自参考资料《银河天使》，是我们自己的产品设计（见 ADR-0001），不是从 Sylpheed 抄来的。

## 结论：三层分开决策

| 层 | 策略 | 理由 |
| --- | --- | --- |
| **框架层** | 照搬 Sylpheed 的**结构**（不搬代码、不搬 ODE / 线程流水线） | 这套结构经过完整商业项目验证，且比原 Lua 版严格 |
| **规则层**（经济 / 机型 / 技能 / 节奏） | **从 Lua 版移植** | 这是我们自己调过的数值与设计，有平衡价值 |
| **表现层** | **全部重写** | 2D 绘制逻辑在 3D 下零价值 |

**不做"全部先移植 Lua 再升级"**。理由：原 Lua 版的不好维护正是来自它的架构
（`core/game.lua` 变成一个什么都知道的巨型状态容器，systems 分散没有依赖方向）。
全量移植等于把技术债一起搬过来，而我们刚花了两轮把架构定对。
正确做法是**移植内容，重建骨架**。

## 采纳的具体机制（按价值排序）

| # | 机制 | 原版做法 | Godot 做法 |
| --- | --- | --- | --- |
| 1 | **编队级集中选靶** | 编队共享目标 Handle，个体不索敌；扫描 1 秒节流；按「预计接近时间」而非裸距离排序；被咬尾时后方目标优先 | 编队持有 target，Timer 节流扫描 |
| 2 | **可抢占行为栈** | 编队决策是可抢占 `deque<CAI*>`，中断命令压栈，原 AI 结束自动恢复 | Array 当栈，行为 = RefCounted + update(dt)->bool |
| 3 | **累加器模式** | 机动 FSM 每帧只写 vAddPosition / quatAddRotation，物理层统一消费 | 单位只写 accum_*，Simulation 末尾统一应用并清零 |
| 4 | **请求-结算两段式** | 创建/删除先进请求表，帧内统一结算 | 自建队列 + call_deferred |
| 5 | **句柄解析** | Handle → Dereference，目标死亡自动失效 | instance_id + is_instance_valid |
| 6 | **间隔任务分桶** | 60 桶均摊，每帧只跑 1/60 | **改成时间预算制**（见下） |
| 7 | **碰撞与伤害解耦** | 碰撞只产 COLLISION_RESULT 消息，伤害由目标侧结算 | signal |
| 8 | **命令化物理提交** | 物理操作入队、先 finite() 校验、统一执行 | 统一在 _physics_process 批量提交 |
| 9 | **主循环五段法** | 结束判定 → 阶段切换 → 常规更新 → 插入检查 → 脚本推进 | SceneDirector 状态机照此顺序 |
| 10 | **参数全进数据表** | per 机型 spec 表 | Resource |
| 11 | **两级火控** | 火控中心 0.1s 分配目标 + 炮塔高频自转 | 对应本作 weapon mount |
| 12 | **概率化机动** | 攻击进入三分支随机、防御概率门槛、瞄准警报闭环 | 群体不塑料，成本低 |

## 明确不搬

| 不搬 | 原因 |
| --- | --- |
| ODE 物理 | 老库单线程，Godot 用 Jolt |
| 双工作线程 + Phase1/Dup1/Phase2/Dup2 四段流水线 | 会与 Godot 渲染服务器/场景树双缓冲打架，自建两套并行模型是灾难 |
| 60 桶固定均摊 | 那是为固定 60fps 调的；我们改为**时间预算制**（每帧给 AI/寻路一个预算时长，超支就顺延） |
| AltiVec SIMD / 32 字节对齐 | PowerPC 专属 |
| double 坐标 | Godot 3D 是 float32，除非做行星尺度 |
| pimpl 8 字节转发、手写 QuickSave 槽 | Godot 有原生能力 |
| 单机体狗斗 FSM | 品类不同：我们是指挥多单位 |

## 代价

- 行为栈比状态机抽象层级高，调试时不容易一眼看出"它现在在干嘛" —— 必须配套行为栈可视化调试
- 时间预算制比固定分桶更难调参
- 移植规则层时要逐条对照 Lua 版行为，有回归风险，靠 gdUnit4 单测兜
