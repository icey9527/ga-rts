# ADR-0013 碰撞：三层碰撞体 + 扫掠弹体 + 命中走信号

- 状态：已采纳
- 日期：S1 前
- 参考：Project Sylpheed 的 CSectorCollider / CUnitCollision / CTask_Shot 体系

## 背景

原 Lua 2D 版：障碍是圆形（x, y, radius），单位可互相重叠，弹体是点，命中靠距离判定。
3D 化后三个问题同时出现：

1. 高速弹体用点判定会**穿透**（一帧移动几百米，直接跨过舰体）
2. 原版没有单位间碰撞，3D 里飞船重叠在视觉上无法接受
3. 舰船有炮塔等独立部件，"打中哪个部件"需要能查

## Sylpheed 的做法（值得借鉴）

同一个单位维护**多套独立几何、分属不同空间**：

| 空间 | 用途 |
| --- | --- |
| hSpace_ForShot | 可被弹体命中（舰体 TriMesh + 部件） |
| hSpace_ForUnit | 单位间阻挡 |
| hGeom_ForAvoidUnit | 规避感知（成对的发射/接收） |
| hDestructibleShotSpace | 可破坏部件（炮塔 / 舰桥） |

弹体的碰撞体**不是点**，是覆盖「上一帧位置 → 当前位置」整段位移的**射线或胶囊**。

## 结论

### 三层碰撞体

| 层 | 用途 | Godot 实现 | 备注 |
| --- | --- | --- | --- |
| hittable | 被弹体命中 | layer 2，ConcavePolygonShape3D（大舰）/ 凸包（小艇） | **只被 ShapeCast 查询，不参与刚体求解** |
| blocker | 单位间阻挡与规避 | layer 3，单个凸包 | 小艇用一个球即可 |
| sensor | AI 感知与分离力 | **不走物理**，自建空间哈希 + 球体 | 数量大，物理开销划不来 |

关键：**hittable 与 blocker 是两套几何，不要复用**。
这解决了"打中判定"和"不撞穿判定"用同一套几何时的相互妥协。

### 弹体一律扫掠

- 弹体位置更新后，用「上一帧位置 → 当前位置」做 `ShapeCast3D`（球扫掠）或 `intersect_ray`
- 不做点碰撞，不做子步进
- 命中点 = 扫掠结果的碰撞点，不是当前位置

这一条**必须做**，不做的话在 3D 尺度下高射速武器会随机穿模，且极难排查。

### 命中与伤害解耦

```
弹体扫掠命中 → 发出 hit(hit_point, target_id, damage_params) 信号
                     ↓
          目标单位自己结算伤害
```

弹体**不**修改目标状态。这样：伤害公式集中在一处、可单测、将来做录像/回放不需要重算物理。

### 部件级命中

大舰的炮塔 / 舰桥挂独立的 hittable 几何，带自己的血量。
命中判定由物理决定（打在哪个形状上就命中哪个部件），不是代码挑。
原 Lua 版的 `weapon_mounts.lua` 只有朝向，没有独立血量，这是 3D 版的升级点。

## 不采纳

| 不采纳 | 原因 |
| --- | --- |
| ODE 空间/几何管理 | Godot + Jolt 已内置宽/窄相位，且多线程 |
| 自建碰撞命令队列 + 三缓冲 | 与 Jolt 的 tick 冲突，收益为负 |
| 全 TriMesh 舰体阻挡 | Jolt 下动态体用 TriMesh 很贵；阻挡用凸包，命中用 TriMesh |
| 碰撞独立线程 | 不需要 |

## 未定

- 是否做"打掉炮塔后该武器失效"的完整部件系统（S2 先做整体血量，S3 再评估）
- 单位间阻挡是否用物理推动还是纯逻辑分离力（初步倾向后者：RTS 里单位被物理推来推去很难受）
