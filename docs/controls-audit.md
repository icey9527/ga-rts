# 操作方式对照：旧版（Love2D）vs 现在（Godot）

> 起因：用户实测后指出「现在的操纵方式和旧版都不一样」。
> 本文逐项核对两边的实际代码，**不是照抄设计文档**。
>
> - 旧版来源：`E:\ai_rts-main\rts_game\battle\input\playing.lua`（214 行，唯一输入文件）
> - 现在来源：`scripts/input/input_router.gd` + `project.godot` 的 `[input]` 段

## 对照表

| 操作 | 旧版（Love2D） | 现在（Godot） | 结论 |
|---|---|---|---|
| 左键拖拽 | 框选 | 框选（4 px 阈值） | ✅ 一致 |
| 左键点己方单位 | 选中 **+ 相机跟随**（`camera:set_follow`） | 选中；跟随需另按 `focus_selected` | ⚠️ **缺自动跟随** |
| 左键点敌方单位 | 已有选中 → **直接攻击**（`direct_attack`）；否则查看+跟随 | 不响应（攻击走右键） | ⚠️ **不同** |
| **右键点击** | **打开上下文菜单**（`show_context_menu`） | **直接发移动/攻击命令** | ❗**设计变更** |
| 右键拖拽 | 平移相机 | 平移相机（拖拽超阈值则不发命令） | ✅ 一致 |
| 中键拖拽 | 无 | 横向平移 + 纵向俯仰 | ➕ 新增 |
| 滚轮 | 缩放（`×1.35^dy`） | 缩放（`camera_zoom_in/out`） | ✅ 一致 |
| 键盘平移 | 无 | WASD（A/S 短按另有语义，需长按才平移） | ➕ 新增 |
| 键盘轨道 | 无 | Q / E | ➕ 新增 |
| **Tab** | **切换单位面板**（`unit_panel:toggle`） | **切 2D / 3D 视图** | ❗**语义冲突** |
| **Space** | 暂停 / 继续 | 暂停 / 继续（本次补上） | ✅ 已对齐 |
| ESC | 取消命令 → 关菜单 → 二次确认退主菜单 | 未实现 | ❌ 缺失（S5） |
| Return | 教程完成后退主菜单 | 未实现 | ❌ 缺失（S5） |
| 高度层 | 无（2D 伪高度） | PageUp / PageDown 三层切换 | ➕ 新增（ADR-0003） |
| 命令菜单（移动/攻击/技能） | 右键上下文菜单是唯一入口 | 直接命令，无菜单 | ❌ 缺失（S5） |

## 判断：哪些是"漏掉"，哪些是"有意重构"

**有意重构（不是 bug，但要让你知道）**
- **右键直接下令**取代上下文菜单：RTS 常见做法，少一次点击；代价是分不出"移动/攻击/攻击移动/技能"。
  若要恢复旧版手感，需要做一个命令菜单（S5）。
- **Tab 改为切 2D/3D**：这是 ADR-0001 双视图的核心操作，旧版没有这个概念。
  冲突在于旧版的单位面板也占用了 Tab —— 面板属于 S5，届时把面板换到别的键（如 `U`）。
- 键盘平移/轨道、高度层：3D 化新增，旧版不存在。

**真正的缺口（本表记录，按优先级）**
1. ~~Space 暂停~~ —— 本次已补（`Simulation.paused` + `toggle_pause` + InputMap `toggle_pause`）
2. **左键点选后相机自动跟随** —— 旧版每次点选都会 `set_follow`，现在要点键
3. **ESC 菜单链**（取消命令 / 暂停确认 / 退主菜单）—— 属于 S5 菜单系统
4. **右键上下文菜单**（移动/攻击/技能/停止的唯一入口）—— 属于 S5
5. **左键点敌人 = 直接攻击** —— 旧版行为，现在把攻击完全放在右键

## 本次已对齐

- `Space` 暂停：`project.godot` 新增 `toggle_pause`（physical_keycode 32）；
  `Simulation.paused` + `set_paused()` / `toggle_pause()`；暂停期间**不累积时间**
  （继续后不会补跑积压的 tick，否则玩家一解除暂停就被瞬间打一波）；
  `InputRouter.pause_toggled` 信号 → `battle.gd` 调 `Simulation.toggle_pause()`。
  验证：`verify_pause`（7 断言）—— 暂停 30 物理帧 tick 一动不动，恢复后继续推进。
